A verification certifies a photo taken live, right now, through a link. An **audit** checks a file that already exists: a photo someone emailed you, one sitting in your system, one you downloaded. No link, no camera, no person on the other end.

By default Rial runs three checks on every audited file: is it a photo of a screen, does it look AI-generated, and is it already online. Describe the photo (`expectedObject`, `context`) and it also checks that it shows that; send `conditionAspects` and it scores the condition. To run fewer of the three, see [Only AI detection](#only-ai-detection). Because no device stood behind the photo, there is no `rial: true/false`; you get the checks that tripped and decide.

## One call

```ts
import { readFile } from 'node:fs/promises';
import { createRial } from '@rial/sdk';

const rial = createRial({ apiKey: process.env.RIAL_API_KEY });

const result = await rial.audits.run({
  file: await readFile('claim-9912.jpg'),
  contentType: 'image/jpeg',
  expectedObject: '2021 Toyota Corolla',
  conditionAspects: ['paint', 'bumper'],
  metadata: { claimId: 'CLM-9912' },
});
```

`audits.run` uploads the file, starts the analysis and waits for the result. It takes a few seconds.

## What you get back

```json
{
  "id": "vfy_…",
  "status": "completed",
  "verdict": { "signals": [{ "type": "ai_detected", "confidence": 0.81 }] },
  "objectMatch": { "status": "match" },
  "condition": { "score": 7.5, "label": "good" }
}
```

- `verdict.signals` lists the checks that tripped. Empty means every check that ran came back clean. `screen_detected` is a photo of a screen, `ai_detected` an AI-generated image, `found_online` an image already published. One check tripping never stops the others, so two can appear together.
- `objectMatch` says whether the photo shows your `expectedObject`.
- `condition` scores each aspect 0 to 10 with a one-line reason.

Every field is explained in [Verdicts](/verdicts).

## Don't wait

`audits.create` uploads and starts the analysis, then returns at once. Read the result later with `verifications.get(id)`, or pass `webhookUrl` and Rial POSTs `verification.completed` to you.

```ts
const started = await rial.audits.create({
  file,
  contentType: 'image/jpeg',
  webhookUrl: 'https://your.app/rial',
  metadata: { claimId: 'CLM-9912' },
});
started.id; // vfy_…
```

## Only AI detection

Pass `checks` to run only the checks you name. `checks: ['ai']` answers one question, does it look AI-generated, and skips the screen and found-online checks.

```ts
const result = await rial.audits.run({
  file: await readFile('receipt-4471.jpg'),
  contentType: 'image/jpeg',
  checks: ['ai'],
  metadata: { orderId: 'ORD-4471' },
});

result.verdict?.signals; // [] or [{ type: 'ai_detected', confidence: 0.93 }]
```

`checks` takes any of `'screen'`, `'ai'` and `'reverse'` (found online). Leave it out and all three run.

Available today in the [sandbox](/sandbox), and in production with the next release. Needs `@rial/sdk` 0.4.0 or later.

## Input

| Field | Required | What it is |
| --- | --- | --- |
| `file` | yes | The bytes: a `Buffer`, `Uint8Array` or `Blob`. |
| `contentType` | yes | `image/jpeg`, `image/png`, `image/webp`, `image/heic` or `image/heif`. |
| `expectedObject` | no | What must appear in the photo. Turns on the object check. |
| `conditionAspects` | no | Aspects to score, up to 6. Turns on the condition check. |
| `context` | no | `{ kind, summary }` describing what the photo is supposed to show. Turns on the context check. |
| `checks` | no | Run only these: `'screen'`, `'ai'`, `'reverse'`. Default: all three. |
| `webhookUrl` | no | HTTPS URL that receives the result. |
| `metadata` | no | Your own keys, returned with the result and in webhooks. |

Audits are billed like verifications. They go through the Node SDK today; for another language, write to developers@rial.io.
